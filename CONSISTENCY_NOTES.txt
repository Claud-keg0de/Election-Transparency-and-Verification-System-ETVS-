ETVS CONSISTENCY-FIXED PROJECT
==============================

Files
-----
schema.sql
    Canonical PostgreSQL schema. result_submissions now has position_id and
    a foreign key to positions, matching candidates, published aggregates,
    audit runs, audit findings and aggregation records.

seed.py
    Idempotent PostgreSQL seed. It can migrate the existing database
    additively: creates missing provenance/position tables, adds missing
    position_id columns, backfills result positions from candidates, creates
    the position foreign keys, and seeds deterministic test data.

audit_engine.py
    PostgreSQL audit engine. Reads source observations and writes audit output.
    Fixes:
      - indentation error
      - PostgreSQL NULL parameter typing
      - position-aware result queries
      - candidate-scoped R004 semantics
      - transaction handling
      - serialized audit hash-chain writers

verify_project.py
    Read-only database consistency checker.

Known errors eliminated
-----------------------
1. column lr.position_id does not exist
   Cause: result_submissions in the live database lacked position_id while
   audit_engine.py and the new schema expected it.
   Fix: schema defines it; seed.py migrates/backfills it and adds FK.

2. IndentationError in audit_engine.py
   Cause: ensure_submissions_validated used inconsistent indentation.
   Fix: normalized to four-space indentation.

3. could not determine data type of parameter $2
   Cause: PostgreSQL could not infer the type of a NULL parameter in a
   position/candidate filter.
   Fix: explicit ::text and ::text[] casts.

4. Audit hash chain INVALID at an old finding
   Cause: prior audit rows may have been produced by earlier hash logic.
   Fix: current engine uses one canonical hash payload and serializes writers.
   For a clean development verification, reset the sample election audit
   records, run one fresh audit, then verify the chain.

5. Repeated reset can fail on provenance dependencies
   Fix: seed.py removes source-submission validation rows and source
   submissions before deleting their source documents.

Run order
---------
1. py seed.py --reset
2. py verify_project.py
3. py audit_engine.py
4. py audit_engine.py --verify-chain

Important
---------
Do not manually add position_id to only one table. The schema, seed and audit
engine must be updated together. This package does that consistently.

The seed deliberately includes anomalies so a successful audit should report
both PASS and FAIL findings. The audit engine does not modify source
observations.



Cross-file integration fixes (2026-09-30)
-------------------------------------------
- web/input_app.py now generates result-submission BLAKE3 hashes using the exact canonical payload used by audit_engine.py R010.
- The polling-station form now reuses an existing registration centre for the selected ward/name and creates deterministic centre IDs only when a new centre is needed; polling stations are no longer used as registration-centre IDs.
- verify_project.py now validates result hash algorithm and canonical result hashes. Use --strict-reference-data after the reference loader and IEBC special-area migration to enforce 6 regions / 47 counties / 290 constituencies / 1,450 wards plus the 2022 prison/diaspora reference totals.
- The feature branch still contains duplicate numeric migration prefixes (004 and 005). They are currently applied lexicographically by CI and do not represent duplicate schema objects, but they should be renumbered in a future migration cleanup.
